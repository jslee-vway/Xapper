# Xapper 에이전트 스킬

Xapper MCP 서버를 쓰는 에이전트에게 작업 절차를 알려 주는 스킬입니다.

서버 지침과 도구 설명은 각각 **초기화 시점**과 **그 도구를 이미 고른 시점**에만 읽힙니다.
스킬은 그보다 앞, 에이전트가 도구를 하나도 고르기 전인 **작업의 첫머리**에 읽힙니다.
그래서 여기에는 개별 도구의 사실이 아니라 화면 하나를 다루는 절차가 담겨 있습니다.

## 설치

스킬은 MCP 서버와 배포 경로가 다릅니다. 서버는 `C:\tools\Xapper\McpServer` 에 게시되지만,
스킬은 Claude Code 클라이언트 쪽에 놓여야 합니다.

Xapper 를 여러 프로젝트에서 쓴다면 사용자 단위로 둡니다.

```bash
cp -r skills/xapper ~/.claude/skills/
```

한 프로젝트에서만 쓴다면 그 프로젝트에 둡니다.

```bash
cp -r skills/xapper <프로젝트>/.claude/skills/
```

어느 쪽이든 Claude Code 를 새로 시작하면 목록에 `xapper` 가 나타납니다.
에이전트가 작업 내용을 보고 알아서 부르며, 사용자가 `/xapper` 로 직접 부를 수도 있습니다.

## 고쳐 쓸 때

앱별 지식은 여기에 넣지 않습니다. "이 앱의 저 버튼은 이렇다" 는 화면 기록
(`xapper_screen_learn` 과 `xapper_screen_note`)이 맡습니다. 스킬은 앱을 가리지 않는 절차만
담아야 여러 프로젝트에서 그대로 쓰입니다.

같은 말을 여러 곳에 적지 않습니다. 안내가 놓이는 자리가 셋이고 각각 읽히는 시점이 다르므로,
무엇을 어디에 둘지 기준이 있습니다.

| 자리 | 언제 읽히는가 | 무엇을 담는가 |
|---|---|---|
| 서버 지침 (`Program.cs`) | 초기화 때 한 번, 늘 | 전체 흐름과 도구 사이의 관계 |
| 도구 설명 | 그 도구를 고르는 순간 | 그 도구를 쓰는 법과 응답을 읽는 법 |
| 스킬 (이 문서) | 작업 첫머리, 불렸을 때만 | 화면 하나를 다루는 절차와 판단 |

서버 지침은 늘 전달되지만 쓰는 순간에서 가장 멀어 잘 잊힙니다. 도구 설명은 그 도구를 쓰면서
못 볼 수가 없으므로, 한 도구의 사실은 거기에 두는 편이 가장 확실합니다. 스킬은 셋 중 가장 강하지만
불려야만 읽히므로, **스킬이 없어도 앞의 둘만으로 일이 되게** 해 두어야 합니다.
